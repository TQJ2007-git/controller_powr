# 设备电量小工具

在 Windows 上同时查看三个外设的电量：**MCHOSE A7 Pro 鼠标**、**MCHOSE G98 键盘**、**Xbox 无线控制器**。

纯 Python 标准库（ctypes + tkinter）实现，**不需要安装任何第三方包**。

## 运行

- 双击 `run.bat`（无控制台窗口）
- 或命令行：`pythonw battery_tool.py`
- 只想看一次数值：`python battery_tool.py --once`

需要 Python 3.9 及以上（带 tkinter，官方安装包默认自带）。

## 界面

- 每 60 秒自动刷新，也可以点「立即刷新」
- 每台设备一张圆角卡片，右侧环形电量随数值增减，按区间变色：≤20% 红、≤50% 橙、其余绿
- 设备不在线时环形显示「—」和原因，不会保留上一次的旧数值
- 「置顶」勾选框默认开启

## 三个设备各自是怎么读到电量的

| 设备 | 通道 | 方法 |
|---|---|---|
| 鼠标 A7 Pro | 2.4G 接收器 `5253:1021` | 私有协议：发送 `0x11` 报告（数据按位取反 `^0xFF`），查询 `0B AA`；回包 `0x13` 按位取反后 `[0]==0xE2`，电量在 `[4]`，充电标志在 `[3]` |
| 键盘 G98 | 2.4G 接收器 `41E4:2001` | V1 协议：先发会话帧，再发电量查询，见下方说明 |
| Xbox 手柄 | 蓝牙 | 读 Windows 自带 PnP 属性 `{104EA319-6EE2-4701-BD47-8DDBF425BBE5}, PID 2`（BTHLE 设备节点），并用蓝牙设备枚举确认当前真的连着 |

手柄有个坑：蓝牙经典地址和 BLE 地址不是同一个（例如 `AA:BB:CC:…` 和 `DD:EE:FF:…` 这样两套），
连上以后两者的容器 ID 也各自独立，所以不能用 MAC 关联。程序是用「设备名 + 当前已连接蓝牙设备列表」
判断的，断开时 Windows 的枚举里就没有它了，因此关机后不会残留旧电量。

### 键盘的 V1 帧格式

20 字节定长，`0x13` 通道：

```
[0]=0x13  [1]=命令  [2]=参数  [3..18]=0  [19]=前 19 字节求和 & 0xFF
```

- 会话：`05 01`（必须先发，否则接收器不响应；接收器会记住会话）
- 电量查询：`4A 01` → 回包 `[1]==0x4A`，电量 `[5]`，充电标志 `[6]`（`0x10` 位 = 充电中）
- 主动推送：`[1]==0x0A` 且 `[5]==0x05` → 电量 `[6]`，标志 `[7]`
- 电量值为 0/1 或大于 100 视为休眠占位，不显示

## 键盘显示「无响应」怎么办

1. 敲一下键盘任意键再点「立即刷新」——键盘休眠时不会应答，查询本身也有唤醒作用。
2. 还是不行就**把 2.4G 接收器拔下来再插回去**。V1 通道的会话是独占的：如果有程序（官方 M HUB、网页版驱动、之前崩溃的窗口）占着会话没释放，接收器会对所有人静音，只有重新插拔才能解除。
3. 确认键盘背面的开关在 2.4G 挡，而不是蓝牙/有线挡。

## 说明

- VID/PID 和协议是按这两款接收器写死的（鼠标 `5253:1021`、键盘接收器 `41E4:2001`）。换设备需要改 `battery_tool.py` 顶部的常量。
- 手柄的电量由 Windows 提供，只有真的连着时才读，避免显示关机前的旧数值。
- 程序只读电量，不发送任何会影响设备设置的命令；键盘的会话帧和查询帧都是官方工具本来就会发的。
